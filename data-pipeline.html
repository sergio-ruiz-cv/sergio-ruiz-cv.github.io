Arquitectura de Datos End-to-End

De la ingesta transaccional al Data Warehouse analítico

El Ecosistema Completo

A diferencia de los pipelines tradicionales que asumen que los datos "simplemente llegan", este proyecto demuestra un dominio Full-Stack Data. Cubre desde el desarrollo de la interfaz operativa que genera la información (Punto de Venta transaccional), hasta la orquestación del flujo ETL y la optimización de consultas en la base de datos columnar.

1. Capa de Origen (Ingesta Transaccional)

Sistema POS (Punto de Venta)

Desarrollé una aplicación frontend interactiva que actúa como la fuente principal de verdad (OLTP). Este sistema gestiona el catálogo, carritos de compra y emite los recibos, generando la volumetría de datos crudos (JSON/APIs) que alimenta el pipeline de backend.

Abrir Emulador POS

Pipeline de Ingesta

Los datos generados por el POS y otras fuentes semiestructuradas (como Google Sheets de inventario) son capturados mediante scripts en Python. Se aplican reglas de validación de tipos, limpieza de valores nulos y estandarización antes de insertarlos en la base de datos de staging.

2. Transformación y Data Warehouse

Una vez capturados los datos transaccionales, el objetivo es transformarlos para que sean útiles en la toma de decisiones empresariales sin afectar el rendimiento del POS.

Staging (PostgreSQL)

Garantiza integridad ACID. Resuelve dependencias de tablas intermedias y almacena los metadatos de las transacciones limpias antes del modelado analítico masivo.

OLAP (ClickHouse)

El núcleo del rendimiento. Al indexar por columnas, permite procesar agregaciones históricas complejas en milisegundos, reduciendo los costos computacionales.

BI (Streamlit / Power BI)

Capa de presentación de alto nivel. Consume las vistas materializadas de ClickHouse para mostrar KPIs financieros y operativos en tiempo real a los gerentes.

Optimización Analítica (Code Snippet)

Ejemplo de cómo los datos del POS son consultados en la capa analítica de ClickHouse. Se eliminan los `JOINs` costosos a favor de agregaciones nativas sobre la tabla desnormalizada.

-- Query para el Dashboard: Rendimiento por categoría desde el POS
SELECT 
    categoria_producto,
    sum(cantidad_vendida) AS volumen_total,
    avg(monto_transaccion) AS ticket_promedio
FROM 
    warehouse.pos_ventas_historicas
WHERE 
    fecha_operacion >= subtractDays(today(), 30)
GROUP BY 
    categoria_producto
ORDER BY 
    volumen_total DESC;
